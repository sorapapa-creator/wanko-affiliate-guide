# サイトのテスト

表示崩れ・リンク切れ・重さの悪化を自動で見つけるテストです。ブラウザ(Chromium)でサイトを開き、決まった項目を確認します。

## 実行方法

リポジトリのルートで次のどれかを実行します。初回は `tests/node_modules` に Playwright が自動で入ります(ルートに `node_modules` は作りません)。

| コマンド | 内容 |
|---|---|
| `npm test` | 全部(スクショ比較・健全性テスト・空室ロジックの単体テスト) |
| `npm run test:visual` | スクショ比較だけ |
| `npm run test:health` | 健全性テストと単体テストだけ |
| `npm run test:update` | 基準画像と基準値を今の状態で作り直す(意図した変更のあとに実行してコミットする) |
| `npm test -- -g food` | 名前に `food` を含むテストだけ(Playwright の引数をそのまま渡せる) |

Chromium がない環境では、先に `cd tests && npx playwright install --with-deps chromium` を実行してください。

## 結果の見方

- `tests/report/index.html` … Playwright のレポート。失敗したスクショは「期待・実際・差分」の 3 枚を見比べられます。
- `tests/report/health-summary.html` … 健全性テストで見つかった問題の一覧(既知・新規)。

## テストの中身

### スクショ比較(`tests/visual/`)

`tests/support/pages.js` の主要 12 ページを、スマホ 375×812 と PC 1280×800 で撮り、`tests/visual/__screenshots__/` の基準画像と比べます。

- `…-first.png` … 開いた直後の最初の画面
- `…-cards.png` … 最初のカード 3 枚が見える位置(上部に固定されたナビの下に 1 枚目が来るようにスクロールし、3 枚目の下端まで撮る)

毎回同じ絵になるように次のことをしています。

- 外部への通信(広告・SNS 埋め込み・地図タイル)は止め、外部の画像は灰色の画像に差し替える
- ブラウザの時計を 2026-10-24 09:00(日本時間)に止める
- 日付(`2026-10-07`・`10/24` など)と件数(`978宿`・`1,067件` など)の数字は「00」に、「空室・満室・残り・在庫・更新・本日」などを含む短い文は「＊＊＊＊」に置き換えてから、ピンクで塗りつぶす(文字の長さが変わっても塗る幅が変わらないように)
- 日付入力欄・`<time>`・`.source-date`・空室を表示しているセレクトは要素ごと塗りつぶす

しきい値は `tests/playwright.config.js` の `maxDiffPixels`(色の違う画素が 20 個を超えたら失敗)と `threshold`(1 画素の色の差の許容 0.2)です。決め方は `docs/health-baseline-20261024.md` にあります。

宿カードの中身の更新など、意図して見た目が変わったときは `npm run test:update` で基準画像を作り直してコミットします。

### 健全性テスト(`tests/health/`)

| 確認 | 失敗する条件 |
|---|---|
| 横スクロール | 375px と 1280px で、実際に右へスクロールできる |
| 主要ボタン 44px | ボタン類・ボタンの見た目のリンクに、44×44px 未満の新しい種類が出た(スマホ) |
| 12px 未満の文字 | 12px 未満の文字の数が基準より増えた(スマホ) |
| 内部リンク・アンカー | リンク先のファイルや `#id` がない(JS で後から作られる id も確認) |
| 広告リンクの rel | アフィリエイトのリンク(バリューコマース・楽天・A8・Amazon の tag 付き・LinkSwitch 対象)に `rel="sponsored"` がない |
| カード数 | 基準から 10% 以上減った |
| HTML の大きさ | 基準から 20% 以上増えた |

主要 12 ページ以外の HTML(サイトマップのページ・SNS 入口など)も、内部リンクと広告リンクの rel だけ HTML を読んで確認します。

「基準」「前回」は `tests/health/baseline.json` の値です。今の main ですでにある問題はそこに既知(`known`)として入れてあり、テストは新しく増えた問題だけで失敗します。既知の問題の一覧は `docs/health-baseline-20261024.md` にあります。問題を直したら `npm run test:update` で既知の一覧からも外してください。

## ページを足すとき

`tests/support/pages.js` の `PAGES` に 1 行足し、`npm run test:update -- -g <ページの id>` で基準を作ってコミットします。
